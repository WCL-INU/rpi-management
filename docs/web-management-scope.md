# Raspberry Pi 웹 관리 페이지 기능 문서

## 목적

로컬 네트워크에 있는 Raspberry Pi 장비들의 현재 상태와 기본 관리 작업을 한 화면에서 확인할 수 있는 작은 웹 페이지를 만든다. 첫 구현은 기존 CLI 스크립트를 대체하기보다, 운영자가 `data/devices.yaml`과 현재 장비 상태를 더 쉽게 파악하도록 돕는 읽기 중심 도구로 시작한다.

## 원칙

- 기능은 작게 시작한다.
- 기존 CLI 스크립트의 동작 방식과 설정 파일 구조를 유지한다.
- 장비에 영향을 주는 작업은 처음부터 자동 실행하지 않는다.
- 비밀번호나 민감한 환경 변수 값은 웹 화면에 그대로 노출하지 않는다.
- 로컬 네트워크 내부에서만 쓰는 것을 전제로 한다.

## 1차 범위

### 장비 목록 보기

- `data/devices.yaml`에 등록된 장비를 읽어 표로 보여준다.
- 표시 항목: 장비 ID, SSH host, 등록된 프로그램 목록, 환경 변수 키 목록
- 환경 변수 값은 기본적으로 숨기고, 키 이름만 보여준다.

### 장비 연결 상태 확인

- 각 장비에 짧은 SSH 명령을 실행해 접속 가능 여부를 확인한다.
- 표시 항목: 온라인 또는 오프라인, 마지막 확인 시간, 실패 시 간단한 오류 메시지
- 상태 확인은 사용자가 버튼을 눌렀을 때만 실행한다.

### 장비 기본 정보 확인

온라인 장비에 대해서만 다음 정보를 가져온다.

- hostname
- uptime
- OS/kernel 정보
- 루트 디스크 사용량

온도, systemd 서비스 상태, CPU/메모리 사용량은 1차 범위에서 제외하고 필요성이 확인되면 추가한다.

### 실행 명령 안내

웹에서 배포 명령을 바로 실행하지 않고, 기존 CLI 명령을 복사하기 쉬운 형태로 보여준다.

- 프로그램 복사: `uv run main.py copy-programs`
- 환경 파일 작성: `uv run main.py write-env-file`
- 프로그램 활성화: `uv run main.py enable-programs`
- 프로그램 업데이트: `uv run main.py update-programs`

## 제외 범위

1차 구현에서 제외한다.

- 웹에서 `devices.yaml` 직접 수정
- 웹에서 배포/업데이트 명령 실행
- 실시간 로그 스트리밍
- 장비 자동 검색
- 사용자 로그인 또는 권한 관리
- 장비별 상세 systemd 제어
- 환경 변수 값 표시 또는 편집

## 이후 후보 기능

필요성이 확인되면 다음 기능을 별도 단계로 검토한다.

- 웹에서 장비 추가/수정
- `upload-*` systemd 서비스 상태 확인
- mDNS 또는 IP 대역 기반 장비 탐색
- CPU, 메모리, 온도 표시
- 웹에서 기존 CLI 작업 실행
- 작업 로그 저장과 조회

## 예상 화면

### 대시보드

- 상단: 등록 장비 수, 온라인 장비 수, 마지막 상태 확인 시간
- 본문: 장비 목록 표
- 우측 또는 하단: 기존 CLI 명령 모음

### 장비 행

| 항목 | 예시 |
| --- | --- |
| 상태 | 온라인 |
| ID | `raspberrypi-1` |
| Host | `raspberrypi-1.local` |
| IP | `192.168.1.100` |
| Programs | `sensor-uploader` |
| Env keys | `SERVER_URL`, `HIVE_ID`, `SENSOR_TYPE_ID` |

## 구현 메모

- 백엔드는 Python 표준 라이브러리 또는 가벼운 프레임워크 중 하나를 선택한다.
- 외부 의존성을 추가하기 전에는 표준 라이브러리 `http.server`로 충분한지 먼저 판단한다.
- 상태 확인 명령은 `ssh -o BatchMode=yes -o ConnectTimeout=4 <host> <command>` 형태를 사용한다.
- 실패한 장비가 있어도 전체 화면이 멈추지 않도록 장비별 timeout을 둔다.
- 쓰기 기능을 추가하기 전까지는 `data/devices.yaml`을 변경하지 않는다.

## 합의가 필요한 질문

- 웹 페이지는 이 컴퓨터에서만 볼 수 있으면 되는가, 아니면 같은 LAN의 다른 PC에서도 접근해야 하는가?
-> 이 컴퓨터에서만 보면 된다. 관리자만 보면 되는 페이지임.
- 장비 상태 확인은 수동 버튼만 있으면 되는가, 주기적 갱신이 필요한가?
-> 경우에 따라 토글할 수 있는 것이 좋다. 기본은 수동 버튼으로 하고, 필요하면 주기적 갱신 옵션을 추가한다. (추후 구현)
- 1차 버전에서 `devices.yaml` 편집 기능이 꼭 필요한가?
-> 꼭 필요하지 않다. CLI에서 편집하는 것이 더 안전하다.
- 배포/업데이트 명령은 웹에서 바로 실행해야 하는가, 아니면 명령 안내만으로 충분한가?
-> 명령 안내만으로 충분하다. 웹에서 직접 실행하는 것은 보안상 위험할 수 있다.
