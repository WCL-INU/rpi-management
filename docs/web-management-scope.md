# Raspberry Pi 웹 관리 페이지 기능 문서

## 목적

로컬 네트워크에 있는 Raspberry Pi 장비들이 현재 동작 중인지, 어떤 상태인지 한눈에 확인할 수 있는 상태 대시보드를 만든다. 첫 구현의 메인 화면은 운영 상태 확인에 집중하고, 설정 파일 내용이나 CLI 명령 안내는 메인 화면에서 분리한다.

## 원칙

- 기능은 작게 시작한다.
- 기존 CLI 스크립트의 동작 방식과 설정 파일 구조를 유지한다.
- 메인 화면에는 장비 상태 판단에 필요한 정보만 둔다.
- 설정 파일 기반 정보는 별도 페이지 또는 이후 기능으로 분리한다.
- 장비에 영향을 주는 작업은 처음부터 자동 실행하지 않는다.
- 비밀번호나 민감한 환경 변수 값은 웹 화면에 그대로 노출하지 않는다.
- 로컬 네트워크 내부에서만 쓰는 것을 전제로 한다.

## 1차 범위

### 메인 상태 대시보드

- `data/devices.yaml`에 등록된 장비를 기준으로 상태 카드를 보여준다.
- 메인 화면의 표시 항목은 상태 판단에 필요한 정보로 제한한다.
- 표시 항목:
  - 온라인 또는 오프라인 상태
  - 장비 ID 또는 표시 이름
  - SSH host 또는 확인 대상 주소
  - Network 상태에 포함되는 IP 주소
  - 마지막 확인 시간
  - 실패 시 간단한 오류 메시지
- 프로그램 목록, 환경 변수 키, CLI 명령은 메인 화면에 표시하지 않는다.

### 장비 연결 상태 확인

- 각 장비에 짧은 SSH 명령을 실행해 접속 가능 여부를 확인한다.
- 표시 항목: 온라인 또는 오프라인, 마지막 확인 시간, 실패 시 간단한 오류 메시지
- 상태 확인은 사용자가 버튼을 눌렀을 때만 실행한다.
- 상태 확인 버튼은 전체 새로고침과 각 장비 카드별 새로고침을 모두 제공한다.
- 전체 새로고침은 등록된 모든 장비를 확인한다.
- 장비별 새로고침은 해당 장비만 확인하고, 다른 장비의 마지막 상태는 유지한다.

### 장비 기본 정보 확인

온라인 장비에 대해서만 다음 정보를 가져온다.

- hostname
- uptime
- RAM 사용량
- Storage 사용량
- Camera 사용 가능 여부 (`rpicam-hello --list-cameras` 기준)
- CPU 활성 상태
- Network 상태
- CPU 온도

systemd 서비스 상태는 1차 범위에서 제외하고 필요성이 확인되면 추가한다. 온도는 Raspberry Pi SoC/CPU 온도로 명확히 표시한다.

### 설정 정보 페이지

- 설정 파일 기반 정보가 필요하면 메인 화면이 아닌 별도 페이지에서 보여준다.
- 1차 구현에서는 별도 페이지를 만들지 않고, 이후 후보 기능으로 둔다.
- 별도 페이지 후보 표시 항목:
  - 등록된 프로그램 목록
  - 환경 변수 키 목록
  - 기존 CLI 명령 안내

## 제외 범위

1차 구현에서 제외한다.

- 웹에서 `devices.yaml` 직접 수정
- 메인 화면에서 프로그램 목록 표시
- 메인 화면에서 환경 변수 키 표시
- 메인 화면에서 CLI 명령 안내 표시
- 웹에서 배포/업데이트 명령 실행
- 실시간 로그 스트리밍
- 장비 자동 검색
- 사용자 로그인 또는 권한 관리
- 장비별 상세 systemd 제어
- 환경 변수 값 표시 또는 편집

## 이후 후보 기능

필요성이 확인되면 다음 기능을 별도 단계로 검토한다.

- 설정 정보 별도 페이지
- 웹에서 장비 추가/수정
- `upload-*` systemd 서비스 상태 확인
- mDNS 또는 IP 대역 기반 장비 탐색
- systemd 서비스 상태 표시
- 웹에서 기존 CLI 작업 실행
- 작업 로그 저장과 조회

## 예상 화면

### 대시보드

- 상단: 등록 장비 수, 온라인 장비 수, 오프라인 장비 수, 최근 확인 시간
- 본문: 장비 상태 카드 또는 상태 중심 목록
- 설정 정보와 CLI 명령은 표시하지 않음

### 장비 상태 카드

| 항목 | 예시 |
| --- | --- |
| 상태 | 온라인 |
| ID | `raspberrypi-1` |
| Host | `raspberrypi-1.local` |
| 마지막 확인 | `14:32:10` |
| 업타임 정보 | `up 3 hours` |
| RAM | `512MB / 1GB` |
| Storage | `4GB / 16GB` |
| Camera | `camera available` |
| CPU | `12% active / load 0.23 / 4 cores` |
| Network | `eth0 up / 192.168.1.100` |
| CPU 온도 | `48.2'C` |
| 새로고침 | 상단 전체 새로고침 버튼, 장비 카드별 상태 확인 버튼 |
| 오류 메시지 | `ssh: connect to host raspberrypi-1.local port 22: Connection refused` |

## 구현 메모

- 백엔드는 Python 표준 라이브러리 또는 가벼운 프레임워크 중 하나를 선택한다.
- 외부 의존성을 추가하기 전에는 표준 라이브러리 `http.server`로 충분한지 먼저 판단한다.
- 상태 확인 명령은 `ssh -o BatchMode=yes -o ConnectTimeout=4 <host> <command>` 형태를 사용한다.
- 카메라 확인은 Raspberry Pi 최신 카메라 스택에 맞춰 `rpicam-hello --list-cameras`를 우선 사용한다.
- 온도는 `/sys/class/thermal/thermal_zone0/temp` 또는 `vcgencmd measure_temp`로 확인한 CPU 온도를 표시한다.
- 실패한 장비가 있어도 전체 화면이 멈추지 않도록 장비별 timeout을 둔다.
- 쓰기 기능을 추가하기 전까지는 `data/devices.yaml`을 변경하지 않는다.

## 합의가 필요한 질문

- 웹 페이지는 이 컴퓨터에서만 볼 수 있으면 되는가, 아니면 같은 LAN의 다른 PC에서도 접근해야 하는가?
-> 이 컴퓨터에서만 보면 된다. 관리자만 보면 되는 페이지임.
- 장비 상태 확인은 수동 버튼만 있으면 되는가, 주기적 갱신이 필요한가?
-> 경우에 따라 토글할 수 있는 것이 좋다. 기본은 전체 수동 버튼과 장비별 수동 버튼을 함께 제공하고, 필요하면 주기적 갱신 옵션을 추가한다. (추후 구현)
- 1차 버전에서 `devices.yaml` 편집 기능이 꼭 필요한가?
-> 꼭 필요하지 않다. CLI에서 편집하는 것이 더 안전하다.
- 설정 파일 기반 정보는 메인 화면에 보여줄 필요가 있는가?
-> 우선 메인 화면에는 보여주지 않는다. 필요하면 별도 페이지에서 보여준다.
- 배포/업데이트 명령은 웹에서 바로 실행해야 하는가, 아니면 명령 안내만으로 충분한가?
-> 명령 안내만으로 충분하다. 웹에서 직접 실행하는 것은 보안상 위험할 수 있다.
